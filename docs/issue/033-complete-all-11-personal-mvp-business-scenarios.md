# Issue 033: 11種類の個人用MVP業務シチュエーション

## 目的

個人用MVPで、受託開発における開始から納品・保守までの主要な顧客折衝を選択して練習できるようにする。
画面固有の分岐を増やさず、共通シナリオ定義へデータを追加する方式を維持する。

## 対象シチュエーション

1. 初回要件ヒアリング
2. 曖昧な要望の具体化
3. 提案・見積もり説明
4. 仕様確認・認識合わせ
5. 仕様変更・追加要望
6. 進捗報告
7. 納期遅延の説明
8. 障害・不具合対応
9. クレーム対応
10. 納品・検収・保守
11. 会議運営

## 振る舞い

- 練習設定画面では、有効な11シチュエーションだけを表示する。
- 各シチュエーションは、一つ以上の具体的場面、開始発話、練習目標、確認対象の事実、評価ルーブリックを持つ。
- 各具体的場面では、難易度1から5を選択できる。
- 事実は、最初から開示するもの、直接質問後に開示するもの、深掘り質問後に開示するものを定義できる。
- 既存の無効fixtureは通常の選択画面に表示しない。
- 新規シナリオの追加は、シナリオ定義データの追加だけで行い、練習設定画面の分岐追加を必要としない。

## 受け入れ要件

- [x] 有効シナリオが上記11件である。
- [x] 各シナリオに少なくとも1件の具体的場面がある。
- [x] 各シナリオが難易度1から5のプロファイルを持ち、少なくとも1場面で全難易度を選択できる。
- [x] 各シナリオの評価ルーブリックが、存在する確認対象の事実だけを参照する。
- [x] 練習設定画面に11シチュエーションが表示され、無効fixtureは表示されない。
- [x] 既存の初回要件ヒアリング、仕様変更、納期遅延の設定・練習フローが回帰しない。

## TDDテスト要件

### Unit Test

- 有効シナリオ一覧が11件の安定したIDを返すこと。
- 各有効シナリオに場面、全難易度、評価対象の事実が存在すること。
- すべてのシナリオ定義がスキーマ検証を通過すること。
- 無効fixtureが通常の選択対象から除外されること。

### E2E Test

- ローカル開発環境を起動して`/setup`を開くこと。
- 11シチュエーションが表示されること。
- 無効fixtureが表示されないこと。
- 既存の初回要件ヒアリングを選択し、デバイス確認画面まで遷移できること。
