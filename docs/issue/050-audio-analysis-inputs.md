# Issue #50: 実際の文字起こしとAI発話区間を音声分析へ連携する

## 目的

音声分析へ空の文字起こしや空のAI発話区間を渡さず、練習中に確定したユーザー発話と、ブラウザ音声合成の開始・終了イベントを使用する。

## 振る舞い

- ユーザーのテキスト入力またはSTT確定結果を、分析用のユーザー発話として時系列に記録する。
- AI応答の再試行時には、同じユーザー発話を二重に追加しない。
- AI顧客の読み上げは `SpeechSynthesisUtterance` の `onstart` と `onend` で実際の発話区間を記録する。
- 練習終了時に、ユーザー発話のみを連結した文字起こしとAI発話区間をローカル音声分析へ渡す。
- STTやTTSが失敗しても、利用可能な入力だけで分析を保存する。

## 受け入れ要件

- 終了時の音声分析に確定済みユーザー文字起こしが渡される。
- AI読み上げの開始・終了時刻を記録し、分析の被せ判定へ渡せる。
- 会話テキストと発話区間は現在の練習セッションだけに紐づく。
- 再試行によって文字起こしが重複しない。
- STTまたはTTSの失敗時も安全に音声分析を完了できる。

## TDDテスト要件

- Unit: ユーザー発話だけを元の順序で連結し、区間はコピーして返す。
- Unit: ブラウザTTSの開始・終了イベントから発話区間を通知する。
- E2E: テスト入力のフィラーが、端末内に保存される音声分析結果へ反映される。
- Regression: 既存のSTT再試行、AI再試行、練習終了フローを維持する。

## 実施結果

- `collectPracticeAnalysisInput` を追加し、ユーザー発話のみを分析文字起こしへ変換した。
- `BrowserSpeechSynthesisAdapter` が実際の開始・終了イベントを記録するようにした。
- 練習終了時に、現在のセッションの文字起こしとAI発話区間を `finishMediaPractice` へ渡すようにした。
- `npm test`、`npm run lint`、`npm run build`、`npx playwright test e2e/scenario-selection.spec.ts` が成功した。
