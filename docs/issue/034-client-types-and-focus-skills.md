# Issue 034: 顧客タイプと重点練習項目の完全な選択カタログ

## 目的

練習設定で、要件定義にある12種類の顧客タイプと16種類の重点練習項目を扱えるようにする。
顧客タイプは表示用の名称だけでなく、AI顧客の会話スタイルとして応答生成コンテキストへ渡す。

## 振る舞い

- 全シナリオは、共通の12顧客タイプを定義する。
- 各具体的場面は、場面と自然に両立する顧客タイプだけを`allowedClientTypeIds`で許可する。
- 練習設定画面では、場面選択後に許可された顧客タイプだけを表示する。
- 顧客タイプには、表示名、説明、協力度、IT知識、AI応答に渡す会話スタイルを持たせる。
- 16の重点練習項目を型安全なカタログとして定義する。
- 各重点項目は、少なくとも一つの有効シナリオで選択できる。
- `アプリに任せる`を選択した場合は、当該シナリオが許可する重点項目から既存の自動選択規則で選ぶ。

## 受け入れ要件

- [x] 要件にある12顧客タイプがすべて定義される。
- [x] 12タイプのそれぞれが、少なくとも一つの具体的場面で選択できる。
- [x] 顧客タイプに会話スタイルがあり、AI APIへ送るコンテキストに含まれる。
- [x] 要件にある16重点練習項目がすべて表示名付きで定義される。
- [x] 16項目のそれぞれが、少なくとも一つの有効シナリオで選択できる。
- [x] 選択した具体的場面と互換性のない顧客タイプを設定画面に表示しない。
- [x] 既存の`アプリに任せる`の自動選択と既存練習フローが回帰しない。

## TDDテスト要件

### Unit Test

- 12タイプの安定ID、会話スタイル、各場面の互換性を検証する。
- 16重点練習項目のラベルとシナリオへの割り当てを検証する。
- 自動重点項目選択が当該シナリオの許可項目だけを返すことを検証する。

### Component / E2E Test

- `/setup`で仕様変更シナリオと具体的場面を選ぶ。
- 要望を頻繁に変更する顧客と反論が多い顧客が表示されることを確認する。
- 互換性のないIT知識が少ない顧客が表示されないことを確認する。
- 断り方と即答しない重点練習項目を選べることを確認する。
